1. What Tickets is (and isn't)

Tickets is a personal lane board. You drive it in the browser, and Claude drives it over MCP. Both share one SQLite file (tickets.db), and every card records who did what.

It sits next to JIRA and similar trackers, not in place of them. Team work, planning with others and anything shared stays there. Tickets is for the local loop: you hand coding tasks to an agent on your machine and review what comes back.

Local and single-person only. It is one process, bound to 127.0.0.1. It has no auth, no accounts and no sync: the person at the board is logged as "User"; agents log under their own names. Never put it on a network, never host it online and never share it with a group.

2. Run it

Start the server (port 8000 is taken on this machine; any free port works if the MCP URL matches):

uv run uvicorn app:app --host 127.0.0.1 --port 8123

Start the agent, in a second terminal:

uv run python agent.py

Give Claude Code the board's tools:

claude mcp add --transport http tickets http://127.0.0.1:8123/mcp

Then open http://127.0.0.1:8123/ and create a project under "projects…". There is no default project, and a card needs one.

3. The board

Lanes

todo → plan → develop → test → verify → done

todo
Your backlog: not started. Move a card on to plan to start it.
plan
The agent writes a plan and any open questions.
develop
The agent builds it, following the plan and your answers.
test
The agent reviews the changes and runs the tests.
verify
The agent is done: you check the result.
done
Finished: nothing more happens to it.

So todo is yours, plan, develop and test are the agent's, and verify and done are yours again.

The header

  • project: shows one project's cards, or all of them.
  • projects…: each project's name, path (the absolute folder of its git repo, where the agent works), agent instructions (how to build, test and deploy, and how to install dependencies in a fresh worktree) and color. "delete project…" moves its cards to "No Project", where agents never work.
  • show archived: shows the archived cards instead.
  • New Card: opens a draft. Nothing is saved until you close it.

Cards

  • Drag a card to another lane, or up and down inside its own column to reorder it: a column is a queue, and an agent takes the top card of it. Dropping anywhere on the page puts it in the nearest column. A card an agent moves lands at the bottom of the lane it arrives in.
  • Moving a card forward (except into done), or back into plan, switches its auto advance on.
  • A card in verify is done work. Change its description, your answers or its checklist there, or add a comment, and you are asking for it again: the card goes back to plan and the agent plans and builds it anew.
  • Click a card to open its sheet. Every field saves as soon as you leave it, so there is no save button; "close" closes the sheet. The sheet holds the description, the plan, the open questions and your answers, the checklist, labels, links (parent and blocks), the activity log, comments and "archive". Cards are never deleted, only archived.
  • A card in verify also has a "move to done" button in its sheet, next to "close": the one click that ends the card.
  • Cards in done have an "archive" button, and the done lane has "archive all" for every done card the board shows.

Signals

  • the dot, left on the card: green when auto advance is on, a faint ring when it is off. Red when it is waiting for you: the agent sets it when it hands a card back, and red wins over green. Any change to the card clears it; just opening the card does not. It pulses while an agent is on the card. A click toggles auto advance; on a red dot it also clears the red and restarts the agent.
  • blue dot, next to it: the card is on master, committed and pushed. purple dot: it is deployed to the local test backend or a device. The agent's deploy sets them; moving the card back to plan, develop or test clears them.
  • status bar, at the bottom: which agent is working on which card, doing what, and since when. Click a card in it to open it.

4. The agent

  • It checks the board every 15 seconds.
  • It picks up a card in plan, develop or test that has auto advance on or is assigned to claude-agent. It skips cards in "No Project".
  • It works one card per project at a time. Different projects run side by side.
  • While it works a card, it assigns the card to itself. Afterwards it gives it back to whoever had it.

Each stage

plan
Claude runs read-only (plan mode) in the project's repo. The plan goes to the card's plan field, and a last ## Open questions section goes to questions. With open questions the card stays in plan and waits for your answers. The description is yours: the agent never writes it.
develop
Claude builds it in auto mode, in the card's own git worktree at <repo>.worktrees/card-<id> on branch card/<id>, and commits there. The project's path must be a git repo.
test
Claude reviews the card's changes and runs the tests. Its reply must end in RESULT: PASS. The agent then commits anything left, pushes card/<id> to origin and moves the card to verify.
deploy
Once a card reaches verify, the agent deploys it once, following the project's instructions — to the local test backend or a connected phone, not production unless the instructions say so — and comments with the result (deployed, skipped or failed), and lights the blue and purple dots. The card stays in verify.

When things go wrong

  • A failed run comments agent failed: …, gives the card back, switches auto advance off and the dot turns red. The card stays in its lane.
  • Running out of quota is not a failure: the agent comments when it will resume, pauses all runs until the limit resets, then picks the card up again where it was.
  • Your move wins: if you move a card during a run, the run's output becomes a comment and the card stays where you put it.

5. How you work with it

  1. Create a project under "projects…". Point its path at a git repo and write its agent instructions.
  2. New Card in todo: a title and a clear description of what you want and why.
  3. Drag it to plan. Auto advance goes on and the agent plans it.
  4. The dot turned red with open questions? Fill in "your answers". That reply restarts the agent, and it replans with your answers.
  5. No open questions: the card carries itself through develop and test to verify. Watch the status bar and the comments.
  6. In verify: read the comments, look at the branch, try the deployed build. Then merge card/<id> yourself, run git worktree remove on its worktree, and move the card to done.
  • When the dot turns red, it's your turn.
  • To stop the agent: switch auto advance off, or move the card to todo. Without auto advance, assign a card to claude-agent to have it do one stage and hand it back.
  • After a failure: read the comment, then fix the description or add a comment. That reply restarts the agent.
  • Not what you asked for? Rewrite the description of the card in verify (or comment on it) and it starts over from plan.
  • Keep one concern per card, keep project instructions current, use links for dependencies, and archive what you no longer need.

6. Other agents over MCP

Any MCP client can use the board at http://127.0.0.1:8123/mcp. The tools: list_cards, get_card, create_card, update_card, comment, link_cards, unlink_cards, create_user, list_projects and set_activity.

  • Every write passes actor, the caller's name, so the log says who did what.
  • An agent assigns a card to itself while it works on it, and gives it back after.
  • Plans go in plan, never over the person's description.

7. Limits

  • No auth, no multiple users, no remote access.
  • No live push: the board polls, so reload if in doubt.
  • No search and no attachments.
  • Cards are never deleted, only archived.
  • The one-run-per-project limit holds for one agent process, not for two started side by side.
