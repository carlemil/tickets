1. What Tickets is (and isn't)

Tickets is a personal lane board. You drive it in the browser, and Claude drives it over MCP. Both share one SQLite file (tickets.db), and every card records who did what.

It sits next to JIRA and similar trackers, not in place of them. Team work, planning with others and anything shared stays there. Tickets is for the local loop: you hand coding tasks to an agent on your machine and review what comes back.

Local and single-person only. It is one process, bound to 127.0.0.1. It has no auth, no accounts and no sync: the person at the board is logged as "User"; agents log under their own names. Never put it on a network, never host it online and never share it with a group.

2. Run it

You need Python 3.12 or newer and uv. Chrome too, but only for the browser tests.

Start the server:

uv run uvicorn app:app --host 127.0.0.1 --port 8123 --log-config log-config.json

Give Claude Code the board's tools:

claude mcp add --transport http tickets http://127.0.0.1:8123/mcp

8123 is the port the repo's scripts use. Any other free port works, but it is not a runtime setting: change restart-backend.ps1 and the claude mcp add URL to match.

Then open the board and create a project under "projects…". There is no default project, and a card needs one.

3. The board

Lanes

todo → plan → develop → test → verify → done

todo
Your backlog: not started. Move a card on to plan to start it.
plan
The agent writes a plan and any open questions.
develop
The agent builds it, following the plan and your answers.
test
The agent reviews the changes and runs the tests, fixing what it can.
verify
The agent is done: you check the result.
done
Finished: nothing more happens to it.

So todo is yours, plan, develop and test are the agent's, and verify and done are yours again.

The header

  • project: shows one project's cards, or all of them.
  • projects…: each project's name, path (the absolute folder of its git repo, where the agent works), agent instructions (how to build, test and deploy, and how to install dependencies in a fresh worktree) and color. "delete project…" moves its cards to "No Project", where agents never work. Adding a project opens a todo card for each thing its setup still lacks — a path, or instructions saying how to test or deploy. Fix it, then archive the card.
  • show archived: shows the archived cards instead.
  • New Card: opens a draft. Nothing is saved until you close it.

Cards

  • Drag a card to another lane, or up and down inside its own column to reorder it: a column is a queue, and an agent takes the top card of it. Dropping anywhere on the page puts it in the nearest column. A card an agent moves lands at the bottom of the lane it arrives in.
  • Click a card to open its sheet. Every field saves as soon as you leave it, so there is no save button; "close", or a click on the board around the sheet, closes it. The sheet holds the description, the plan, the open questions and your answers, the checklist, labels, links (parent and blocks), the activity log, comments and "archive". Cards are never deleted, only archived.
  • An agent's comment has a "claude's output" box under it, closed: open it to read the whole run as you would have seen it in the terminal — every file it read, every command it ran, and what it cost.
  • A card in verify also has a "move to done" button in its sheet, next to "close": the one click that ends the card.
  • Ctrl- (or ⌘-) click toggles a card in the selection; shift-click takes the whole run from there to the card, as long as both are in the same lane. Dragging one card of a selection moves all of them; dragging an unselected card moves it alone. A plain click clears the selection and opens the card, and Esc clears it.
  • Cards in done have an "archive" button, and the done lane has "archive all" for every done card the board shows.

Signals

  • the first dot, left on the card: it fills and pulses while an agent is working on the card, a faint ring otherwise.
  • blue dot, next to it: the card's branch is on the project's base branch, set by the agent's deploy step. purple dot: it is deployed to the local test backend or a device, lit by the agent's deployed: comment. Moving the card back to plan, develop or test clears them.
  • status bar, at the bottom: which agent is working on which card, doing what, and since when. Click a card in it to open it.

4. The agent

Nothing works the board by itself. You start the work by hand: open a Claude Code session in the project's folder and run the /tickets skill. It works every ready card of that project in plan, develop and test through to verify, and writes what it does onto the board as claude-agent: the plan, comments, the moves, and a new idea card for any follow-up it finds. Cards in "No Project" are never worked.

5. How you work with it

  1. Create a project under "projects…". Point its path at a git repo and write its agent instructions. Whatever you leave out shows up as a card in todo telling you what is still missing.
  2. New Card in todo: a title and a clear description of what you want and why.
  3. Drag it to plan, then run /tickets in the project's folder. Watch the status bar and the comments.
  4. Open questions in the plan? Fill in "your answers" and run /tickets again: it replans with them.
  5. In verify: read the comments, look at the branch, try the deployed build. Then merge card/<id> yourself and move the card to done. A project whose deploy instructions do the merge leaves you only the last one.
  • Not what you asked for? Rewrite the description, move the card back to plan and run /tickets again.
  • Keep one concern per card, keep project instructions current, use links for dependencies, and archive what you no longer need.

6. Other agents over MCP

Any MCP client can use the board at http://127.0.0.1:8123/mcp. The tools: list_cards, get_card, create_card, update_card, comment, link_cards, unlink_cards, create_user, list_projects and set_activity.

  • Every write passes actor, the caller's name, so the log says who did what.
  • Plans go in plan, never over the person's description.

7. Limits

  • No auth, no multiple users, no remote access.
  • No live push: the board polls, so reload if in doubt.
  • No search and no attachments.
  • Cards are never deleted, only archived.
